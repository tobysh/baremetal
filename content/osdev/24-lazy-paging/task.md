The `Region` type, page-table flag constants, `frame_alloc` (returns the physical address of a free 4 KiB frame, or 0 when none are left), `map_page(virt, phys, flags)`, `read_cr2()`, `panic(msg)` and the counter `uint64_t pages_faulted` are in the starter. Implement:

- `int vm_region_add(uint64_t start, uint64_t len, int writable)` registers a lazy region and returns 0, or returns -1 (changing nothing) if: `start` or `len` is not a multiple of 4096; `len` is 0; the range wraps or reaches past `0x00007FFFFFFFFFFF`; it starts below `0x40000000` (the first GiB is already mapped by the boot code); it overlaps a registered region; or four regions are already registered.
- `int pf_handle(uint64_t addr, uint64_t err)` decides one fault. It returns 1 after mapping a new zeroed page at `addr` rounded down to 4096, with `PTE_PRESENT` and also `PTE_WRITABLE` if the region is writable, and adds 1 to `pages_faulted`. It returns 0 and changes nothing if the error code says the page was present (bit 0), it was an instruction fetch (bit 4), it was a write to a read-only region, the address is in no region, or no frame is available.
- `void pf_exception_handler(uint64_t vector, uint64_t error_code, uint64_t rip)` handles one exception: for vector 14 it calls `pf_handle` with the address from `read_cr2()` and returns if the fault was accepted. Any other exception, or a refused fault, calls `panic`.
- `void vm_init(void)` forgets all registered regions, resets `pages_faulted` to 0 and sets `bm_exception_hook` to `pf_exception_handler`.
