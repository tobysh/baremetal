## 1. C, asm and osdev

### New lessons
- **Sanitizers and gdb** (`c-memory`, before `c-debugging`): ASan/UBSan/Valgrind, gdb basics, core dumps. Nothing covers them; `c-debugging` is custom harnesses only.
- **Multi-file C** (`c-systems`): translation units, include guards, `static`/`extern`, opaque-pointer APIs, Makefiles.
- **`c-linux-internals`:** mmap and shared memory, pipes/FIFOs and select, directory walking, `/proc` parsing.
- **`c-networking`:** HTTP/1.0 parser and server, epoll event loop, DNS packet parser.
- **`c-concurrency`:** reader-writer lock, bounded producer-consumer queue, intermediate lock-free stack (the jump from 09 to the lock-free ring 11 is steep), ABA/hazard pointers.
- **`asm-systems`:** variadic calls (AL), System V struct passing, raw Linux syscalls, floating-point compare/branch.
- **`asm-first-steps`:** explicit lessons on addressing modes, and flags with conditional jumps.
- **`osdev`:** APIC/IOAPIC, ATA/AHCI disk read, keyboard/mouse input, double-fault handler with IST.
- **`osdev-2`:** fork/exec/wait, FAT or ext2 reader, signals, futex/blocking mutex.
- **`first-steps`:** arrays or strings preview, simple functions with pointers.
- **`c-embedded`:** volatile/barriers/DMA descriptors, fixed-point math and CRC.
- **`c-performance`:** perf/gprof profiling, branch prediction and SIMD intrinsics.
- **`c-model-checking`:** linearizability, liveness/fairness.
- **`c-data-structures`:** red-black or AVL tree, union-find, priority queue/Dijkstra.

### Progression
- `c-memory` puts bit masks (14, 15) last, but `c-embedded` and `c-networking` need them.
- `c-memory/12-linked-lists` precedes its review, and `c-data-structures/04` repeats the idea.
- `c-systems` has 7 lessons and no capstone beyond the hash table.
- `c-practice` looks like leftover topics with inconsistent prerequisites.
- `osdev` ordering looks non-monotonic: easy lessons (cpuid, cmos, pci) come after the ELF loader, and `24-lazy-paging` follows the review.
- `osdev` has no standalone interrupt-handling lesson and no real boot lesson.
- No gdb-for-asm coverage.
- No cross-language "see also" links.

### Overlaps
- Dynamic array: `c-data-structures/01` and `c-systems/03` (and `04`).
- Hash table: `c-systems/07` and `c-data-structures/09, 10`.
- Tokenising: `c-systems/05`, `c-shell/01`, possibly `c-practice/08`.
- Sorting: `c-practice/04` and `c-data-structures/05-07`.
- BST: `c-practice/07` and `c-data-structures/11`.
- Deque/ring buffer: `c-practice/06` and `c-data-structures/03`.
- Arena: `c-allocators/02` and `c-performance/04`.
- Kernel heap: `osdev/10` and `osdev-2/07`. Frame allocator: `osdev/07` and `osdev-2/06`.
- Syscalls and scheduling: `osdev/13` vs `osdev-2/03`; `osdev/11, 12` vs `osdev-2/05`.
- Deadlock: `c-concurrency/04`, `c-model-checking/04`, `c-debugging/03` (fine if cross-referenced).

## 2. Rust and Go

### New lessons
- **Rust:** unit tests and assert macros, testing errors/panics, Cargo features; async/await with a mini executor and waker; unsafe Rust (`MaybeUninit`, `transmute`, safe wrappers, `// SAFETY:` contracts, a Vec built on `alloc`); `Rc`/`RefCell`/`Weak` as separate lessons; `macro_rules!`; `Cow`/`AsRef`/`Borrow`/`Into`; `FromStr` and `Display` parsing; an Iterator deep-dive.
- **Go:** testing basics (subtests, benchmarks, fuzzing), possibly earlier than `go-services` 12; `flag`/`os.Args`/stdin CLI tool; generics II; pprof, `-race`, `go vet`, `go mod`; `sync.Pool`, `sync.Map` and the memory model; pipeline and cancellation patterns; graceful shutdown with `net/http`; raw `net` TCP.

### Progression
- `rust-foundations/13-hashmaps` sits after error handling and before `rust-bridge`; `rust-bridge/12, 13` are basics at the end of a bridge track.
- `rust-intermediate` mixes lifetimes, errors and threads.
- `rust-practice` has no hard capstone. `rust-interpreter` lacks only a GC/heap lesson.
- `go-foundations` 15 to `go-database`/`go-filesystems` is a steep jump. The specialist Go tracks have no stated prerequisites.
- Both languages lack file I/O basics and Rust lacks logging.

### Overlaps
- `rust-intermediate` 13-16 (threads) vs `rust-concurrency` 03, 04, 07.
- Lifetimes, generics and trait objects: `rust-intermediate` vs `rust-traits`.
- `rust-foundations/07` vs `rust-bridge/01` vs `rust-practice/01`.
- Several review capstones may repeat domains (log analyzer vs log summary, inventory twice).
- Go goroutines/sync: `go-foundations` 13-14 vs `go-concurrency` 01-05.
- Go retry: `go-services/05`, `go-fault-injection/05`, `go-distributed/01`.
- Go fake clocks: `go-fault-injection/04` and `go-services/14`.
- `go-concurrency/11` vs `go-services` 01-04.

## 3. Security

Framing is consistently safe (toy targets, simulated data, defender counterpart). Detection, forensics and appsec are strong.

### New lessons
- **`sec-c-bugs`:** integer-width truncation in allocation; heap overflow into an adjacent chunk (deterministic model).
- **`sec-appsec`:** CSP/CORS header evaluator; deserialization/XXE-style expansion limits.
- **`sec-crypto`:** key derivation and separation (HKDF-style); error-oracle uniformity (after `16-padding-check`).
- **`sec-detection`:** Sigma-style rule compiler; beaconing/periodicity detection.
- **`ethical-hacking`:** cloud IAM over-permission audit; container/CI secret exposure.
- **Rust:** no security track. A memory-safe parser compared with `sec-c-bugs/09-tlv-parser`.
- **Missing topics:** OAuth/OIDC, TLS and certificate validation, wireless, Windows/AD, supply-chain detection beyond lockfiles.

### Structure
- The path switches from C to Go without warning. `sec-synthetic-labs` needs `go-practice` but follows advanced C tracks.
- `sec-incident-response`, `sec-secure-delivery` and `sec-reverse-engineering` are all order 12. The `sec-infra-offense`, `sec-toy-maldev` and `sec-incident-response` prerequisite chain does not make sense.
- `sec-infra-offense` is all hard with no easy on-ramp. `sec-toy-maldev` is 16 hard lessons with a steep jump at 05.
- `ethical-hacking` 22-24 appear appended after the 21 capstone.

### Overlaps
- Scan detection: `ethical-hacking/03`, `sec-packets/11`, `sec-synthetic-labs/07`.
- Password cracking: `ethical-hacking/12`, `sec-crypto/14, 15`.
- Persistence: `ethical-hacking/13`, `sec-infra-offense/06, 07`.
- Lateral movement/privilege: `ethical-hacking/16`, `sec-synthetic-labs/08`, `sec-incident-response/05`.
- Timelines: `ethical-hacking/18`, `sec-forensics/09`, `sec-incident-response/01`.
- IDOR/authorization: `ethical-hacking/10, 22`, `sec-appsec/10`.
- Sessions: `ethical-hacking/10`, `sec-appsec/04`.
- Path traversal: `ethical-hacking/23`, `sec-c-bugs/10`.
- Incident stitching: `sec-detection/12`, `sec-incident-response/02`.

### Safety checks to do

- `sec-toy-maldev` `solution.go` files: confirm no real syscalls or network calls.

## 4. Platform (`src/`)

The agent did not read the UX, tutor, diagnostics, gamification or accessibility code, so items under 4d are inferred.

### 4a. Uncommitted edits
- `auth.ts`: drops unused `toObjectId`. Fine.
- `runner-engine.ts`: adds a `settled` guard for spawn errors and un-exports `literalMask`. Fine, but check that the caller treats "Sandbox could not start" as a runner fault, not a learner failure.
- `instrumentation.ts` and `runner-resources.ts`: add `cleanupStaleCgroups()` at boot.
  - It only runs when `RUNNER_SOCKET` is unset (dev path). The production runner service must call it itself.
  - The 15-minute mtime cutoff could kill a live job from a second runner instance.
  - `cgroup.kill` needs Linux 5.14 or newer.
  - No tests, and no mention in `docs/security.md` or `docs/deployment-hardening.md`.
  - `readdir`/`stat` failures are swallowed silently.

### 4b. Testing
- There is no unit-test framework. Add Vitest or `node:test` via `tsx`, wired into `package.json` and CI.
- Start with the pure security-critical modules: `literalMask` and `harnessTampering`, `redirects.ts`, `password-policy.ts`, `totp.ts`, `crypto.ts`, `rate-limit.ts`, `tutor-normalize.ts`, `error-lines.ts`, and XP/streak logic in `gamification.ts` and `rhythm.ts`.
- Table-test `diagnostics.ts` against real compiler and runtime output.
- Add one `npm run check` that runs `check:theme` and `verify:content`.

### 4c. Hardening and operability
- Per-job cgroup limits and the memory-bomb check have never run on a real host. A staging checklist or script is missing.
- `docs/shell-deployment.md` is unverified. Open items: vsock handoff, invented env var names, the launcher VM cap variable, a transport for a separate shell host, lab-network launcher code, guest kernel never booted, SMT handling, one uid per session, and abuse controls.
- Known limitation: transcript forgery by code sharing a process with its harness. The real fix is to move the verdict out of process.
- A strict nonce CSP is deferred because of partial prerendering.
- Add health and metrics endpoints for runner queue depth, rejections and cgroup cleanups.
- `scripts/check-theme.mts` TODOs: `manifest.ts`, the `layout.tsx` viewport `themeColor` and `global-error.tsx` need literal colours. Use a shared constants module and a check against the `--bg` tokens.

### 4d. Unconfirmed ideas

- Respect `prefers-reduced-motion` in celebrations, and don't convey XP, streak or failure by colour alone.
