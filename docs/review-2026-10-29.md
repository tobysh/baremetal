# Improvement review

Updated 30 October 2026. This replaces the initial read-only review from 29 October;
its uncommitted-file counts and several missing-feature claims were stale. The
current work is organised below by implementation versus deployment evidence.

## Implemented

| Area | Current behaviour | Verification |
| --- | --- | --- |
| Learning journey | Shared resume/course-transition recommendations, beginner-to-C default, optional prerequisites, authored outcomes; stable exercise IDs preserved. | Recommendation and prerequisite fixtures; browser course-transition checks. |
| Failure feedback | Existing diagnostics now include a next debugging step, retain raw output and diffs, and explain unmatched runtime failures. | Diagnostic fixtures and workspace checks. |
| Draft reliability | Serialized account saves, stale-response protection, scoped browser recovery, retry actions and cancellation on navigation. | Browser failure, delayed-save, reload, navigation and storage-disabled scenarios. |
| Learning measurement | Admin-only weekly course cohorts from existing progress; small groups hidden, missing dates excluded, later activity explicitly distinguished from retention. | Deterministic cohort fixtures and admin-access checks. |
| Runner boundary | Execution engine extracted; versioned, bounded Unix-socket service owns admission, queueing and cancellation. Production requires the socket; web auth/progress/rewards stay in the web service. | All five languages over the socket; admission, full queue, cancellation and unavailable-service checks; full curriculum and forged-verdict fixtures. |
| CI | Types, lint, guards, content and build checks plus isolated database-backed auth/budget/API/browser checks. | Scripts run locally; GitHub workflow execution remains a CI-host check. |
| Deployment material | Dedicated web/runner units, delegated cgroup setup and disposable-host verification script. | Unit-file validation; real-host checks below remain pending. |

Already present before this implementation: CI/content guards, backup/restore
scripts, tutor spending reservations, anonymous execution across lessons, the
admin stuck view, basic workspace keyboard support and profile `notFound()`
handling. These should not be treated as missing features.

## Active backlog requiring external evidence

1. Install separate web/runner users and units on a disposable deployment copy.
   Run the host isolation/cgroup probe and verify recovery after runner restart.
   Templates alone do not establish host isolation.
2. Verify SMTP delivery, worker scheduling, email verification and password
   recovery with a real mailbox. Exercise backup restore on the deployed setup.
3. Observe five beginners using the opening lessons and entering C; record
   concrete instruction changes in `learning-validation.md`.
4. Complete a screen-reader pass. Browser keyboard/viewport tests do not replace
   assistive-technology testing.
5. Check the cohort report once sufficient real learner data exists before
   expanding tracks or rewards. Its later-activity metric is a lower bound on
   same-course learning, not login retention.

## Accepted architectural limitations

The sandbox and web services still share a host kernel. Same-process lesson-test
verdict forgery remains bounded rather than eliminated; do not treat leaderboard
scores as independently verified results. CSP still permits inline scripts.
Details and the launch checklist remain in `security.md` and
`deployment-hardening.md`.
