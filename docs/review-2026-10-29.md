## 2. Security

- 2.1 Sandbox runs as the web server's uid; escape (bwrap or QEMU device emulation) reaches `.env.local`, the Anthropic key and Mongo. Treat a separate runner uid/service as a launch blocker. **Not started: needs the real host.**
- 2.2 Per-job cgroup limits never exercised on a real host; memory bomb untested. **Host verification needed.**
- 2.3 Seccomp is a denylist; new syscalls slip through. Consider an allowlist.
- 2.4 Same-process test forgery (C/asm trivial for a determined user; Go/Rust have no nonce). Leaderboard and public profiles will attract cheaters; do not add prizes.
- 2.5 CSP keeps `script-src 'unsafe-inline'`. Unaudited: `achievements.ts`, `rhythm.ts`, `inline-script.tsx`, client workspace code. Audit before launch. **Agent: audit.**
- 2.6 `ethical-hacking` / `sec-*` tracks: terms need an acceptable-use line; sandbox has no network, so say so. Tutor abuse policy should cover pasted tooling output.

## 3. Product and pedagogy

- 3.1 "Free" sits on uncapped tutor token cost; the per-user daily dollar ceiling is still on the to-do list. Define what free degrades to when the budget runs out (pre-written diagnostics). **Agent: tutor budget.**
- 3.2 Landing page promises "from zero" to an HTTP server, but the path jumped from `first-steps` to `c-memory` without arrays, strings and structs (`c-data` is the fix but was untracked). Fix path order before more tracks.
- 3.3 Breadth outruns depth: 32 tracks, 371 lessons, few challenges. Freeze new tracks; finish the admin "where learners get stuck" view (`stuck.ts` exists).

- 3.5 Signed-in users are redirected away from `/`; anonymous visitors can only try hello-world. Consider letting anonymous users run the first 3 to 5 lessons unsaved.
- 3.6 Signup now needs email verification, but SMTP and the delivery worker are not scheduled. Test the full path with a real mailbox.
